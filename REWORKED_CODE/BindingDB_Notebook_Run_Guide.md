# CTDDG BindingDB preparation and conditional fine-tuning

## What to run

1. Open `BindingDB_Data_Preprocessing.ipynb` on the IIT Palakkad HPC system. In its configuration cell, check `REPO_ROOT`, `BINDINGDB_ROOT`, `ATOM_TYPES_FILE`, `RF_DIR`, `PRETRAIN_CHEMBL_FILE` and `OUTPUT_DIR`. The selected model and metadata are expected at `REWORKED_CODE/Random_Forest/rf_outputs/best_ames_rf.joblib` and `best_ames_rf_metadata.json`, as produced by the uploaded `RF.ipynb`. If `RF.ipynb` was executed from a different working directory, adjust `RF_DIR`; do not substitute the unrelated historical `ames_random_forest.pkl`.
2. Check that the fold-specific `d1_tr/te_unique_proteins.txt`, corresponding `d1_tr/te_unique_proteins_bepler.fa` and `d1_tr/te_unique_embeddings_bepler.h5` exist. The embedding HDF5 files must contain `p1..pN` arrays of length 6165 in the exact FASTA order. If missing, run the **existing** `01_generate_prose_embeddings.ipynb` (ProSE, `--pool avg`) first; do not randomly initialize protein embeddings.
3. Set `RUN_PREPROCESSING=True`, execute the preprocessing notebook in order, and inspect `dataset_manifest.json`. It writes new versioned train/val/test TSVs, RF provenance, data hashes, filtering counts, and a direct anti-leakage check comparing canonicalized BindingDB ligands across **all five folds** to the **exact stage-1 ChEMBL file**. It never writes over existing datasets. If necessary, change `OUTPUT_DIR` to a fresh suffix.
4. In `CTDDG_BindingDB_Finetuning.ipynb`, verify `DATA_DIR`, `PRETRAIN_RUN_DIR`, `PRETRAIN_CHECKPOINT`, `PRETRAIN_META`, `ATOM_TYPES_FILE` and `RUN_DIR`. It expects the **specific PyTorch model class** `CTDDGPretrainer` from the uploaded `CTDDG_pretraining_final(2).ipynb`, and `run_meta.json` with `model_config`, `atom_types_sha256` and `chembl_sha256`. It does **not** load the older MXNet or older `02_finetune_ctddg` checkpoint.
5. Run the fine-tuning notebook once with `RUN_TRAINING=False`. It checks the data/label/protein contracts, verifies the stage-1 ChEMBL hash against the exclusion audit, transfers every common pretrained parameter, runs a conditional forward/backward self-test and measures step-zero validation likelihood. **Do not disable failing provenance checks to obtain paper-level results.**
6. Once the preflight checks pass and the pretraining checkpoint's molecular validity has been independently checked, set `RUN_TRAINING=True`. Submit the work through an approved GPU/Slurm allocation. It writes `ckpt_last.pt`, `ckpt_best.pt`, `train_log.jsonl`, `val_log.jsonl`, `run_meta.json` under the versioned `RUN_DIR`.
7. To resume after a normal/abrupt exit, rerun the unchanged fine-tuning notebook with `AUTO_RESUME=True`, the **same** run directory and input files. It restores model/optimizer, all RNG states, epoch, within-epoch batch position, learning-rate schedule and early-stopping counters; the latest checkpoint has a `.prev` fallback. If input files or the configuration changed, use a new run directory. The active logs are reconciled with the durable checkpoint while preserving orphaned rows separately.

## Research cautions

- BindingDB labels are predictions made by **the selected Random Forest**, not measured Ames labels. The published CTDDG paper used **pkCSM** on BindingDB; this is a documented methodological deviation. The previous RF's historical Hansen training overlap is not established, even if it had a higher comparison score.
- Old ChEMBL preprocessing once identified only seven BindingDB structures due to a full-line SMILES parsing mistake; the new notebook reconstructs complete lines and *checks the actual pretraining file*. A recorded zero-leakage result on another file is insufficient.
- The **exact ordered atom vocabulary** must match pretraining. Do not create a new BindingDB vocabulary or assume the older published 65-type file is compatible with a new 36-/43-type PyTorch checkpoint.
- CTDDG's signed toxicity likelihood objective (Equation 8) can diverge. A negative total loss or dropping toxic likelihood does not establish improved generated molecule validity/toxicity. The default checkpoint-selection metric is held-out non-toxic likelihood; independently evaluate generation and docking later.
- Dataset evaluation uses the original novel-protein test fold. A 5% subset of training proteins is carved out for validation, preserving the held-out test proteins; identity checks do not by themselves re-prove the paper's 20% sequence-similarity criterion.
- A CPU-only synthetic test of the notebooks was successful, including full data preparation, model transfer, a conditional forward/backward test, one fine-tuning epoch, and checkpoint recovery. **The actual HPC raw BindingDB files, RF weights and pretraining checkpoint were not uploaded here; no production fine-tuning job has been executed.**
